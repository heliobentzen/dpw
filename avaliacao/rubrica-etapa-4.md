# Rubrica — P4: Relatório e encerramento

> **Peso:** 20% · **Entrega:** semanas 19–20 · **Eliminatória** · Orientações em
> [`projeto/etapa-4-relatorio-e-encerramento/`](../projeto/etapa-4-relatorio-e-encerramento/)
> Escala por critério: 4 Excelente · 3 Adequado · 2 Em desenvolvimento · 0–1 Insuficiente

**Equipe:** `<...>` · **Data:** `<...>`

**O que esta rubrica verifica:** se a equipe sabe explicar e justificar o que construiu, se
mediu o resultado com honestidade e se deixou o sistema pronto para ser entregue a quem
vai mantê-lo. A transferência **real** a uma organização é avaliada só no
[bônus de parceria](rubrica-extensao.md), que é opcional.

## Critérios

| Critério | Peso | 4 — Excelente | 3 — Adequado | 2 — Em desenvolvimento | 0–1 — Insuficiente | Nível |
| --- | ---: | --- | --- | --- | --- | :---: |
| **1. Decisões técnicas** | 2,0 | Arquitetura, modelo e contrato explicados com diagramas; decisões comparadas com alternativas (ADRs) | Decisões principais justificadas | Descreve tecnologias em vez de justificar escolhas | Sem justificativa | |
| **2. Resultados e limitações** | 2,0 | Metas da P1 comparadas com o medido no teste com usuário; o que não foi alcançado é analisado; bugs e dívidas declarados | Resultados com evidência e limitações declaradas | Resultados afirmados sem evidência | Ausentes ou maquiados | |
| **3. Escrita** | 1,0 | Clara, objetiva, no limite de páginas; figuras e referências citadas | Clara e organizada | Confusa ou com enchimento | Genérica | |
| **4. Demonstração** | 2,0 | Ao vivo, em produção, com o cenário principal e um caso de erro ou acesso negado | Funciona em produção, no cenário principal | Em `localhost` ou com falhas | Não demonstrou | |
| **5. Domínio técnico** | 2,0 | Cada integrante explica com precisão partes que não escreveu | Equipe responde corretamente às perguntas | Respostas superficiais | Não sabem explicar o próprio sistema | |
| **6. Pronto para transferir** | 1,0 | Termo de transferência preenchido (contas, acessos, custo mensal, backup, quem administra); `docs/manutencao.md` e `docs/deploy.md` que outra pessoa segue sozinha | Documentação de deploy e manutenção completa, com custos | Documentação parcial | Só o código | |
| **Total** | **10** | | | | | |
