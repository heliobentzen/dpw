# ➕ Trilha opcional: parceria com a comunidade

> **Opcional** · **Vale:** até **+1,0** na média final ·
> **Rubrica:** [`rubrica-extensao.md`](../../avaliacao/rubrica-extensao.md)

## O que é, e por que é opcional

Todo projeto da disciplina é pensado **para** uma comunidade: um tipo de organização ou grupo
real, com um problema plausível. Mas o projeto **não depende** de uma organização de verdade:
a equipe pode pesquisar, montar personas e construir a API inteira sem nenhum compromisso
externo. É isso que todas as equipes fazem.

Esta trilha é para a equipe que quer — e consegue — ir além: levar o sistema a uma
organização real, ver alguém de lá usando e devolver o resultado. É a parte mais rica da
experiência, e também a mais sujeita a fatores fora do controle da equipe (agenda da
organização, internet no local, pessoas que mudam). Por isso ela vale **bônus**, e não
nota obrigatória.

> **Extensão curricular:** se o PPC atribuir a esta disciplina carga horária extensionista
> com interação real, a coordenação do curso pode tornar esta trilha obrigatória; ver o
> [plano de ensino](../../docs/plano-de-ensino.md#10-adaptações).

| ✅ Conta para o bônus | ❌ Não conta |
| --- | --- |
| A organização confirma o problema | A equipe decide sozinha o que a comunidade precisa |
| Encontros ao longo do semestre | Uma visita para tirar foto |
| Algo fica e é usado | Apresentação de slides e ida embora |
| Devolutiva registrada | Sem retorno |

## Como seguir a trilha

Avisem o docente até a **P1 (semana 4)**. Os passos acompanham o projeto que vocês já fazem:

| Semana | Com a organização | Usa o que já existe |
| ---: | --- | --- |
| 2–4 | Conversa sobre o problema; aceite por escrito ([carta de anuência](../modelos-de-documentos/carta-de-anuencia.md) ou e-mail); ata | P1: o problema e as personas passam a ser validados, não só pesquisados |
| 6–10 | Mostrar o cenário principal funcionando | P2 |
| 14 | Visita ao local: abrir o `/api/health` no equipamento de lá | M12 |
| 16 | Teste com usuário feito por alguém da organização | P3, critério 4 |
| 19 | Implantação com dados reais e capacitação | — |
| 20 | Devolutiva e transferência real das contas | P4, critério 6 |

### Roteiro da primeira conversa (20 minutos)

1. Como o processo funciona hoje, do começo ao fim?
2. Quem participa? Quantas pessoas? Com que frequência?
3. O que dá errado com mais frequência?
4. Se pudessem resolver **uma** coisa, qual seria?
5. Quem usaria o sistema? Têm celular, internet, computador?
6. Quem cuidaria do sistema depois?

### Capacitação é mão na massa

1. Demonstre o fluxo uma vez.
2. Cada pessoa executa sozinha, enquanto você observa **sem intervir**.
3. Tire as dúvidas e repita.

### Devolutiva

Na linguagem da organização: o que combinamos e o que fizemos; o que mudou, com números; o
que fica (sistema, acessos, guia, custo); e **escuta** — o que funcionou, o que atrapalhou.
Registrem a fala da organização e escrevam o
[relato de experiência](../modelos-de-documentos/relato-de-experiencia.md).

## Cuidados

- **Não prometam o que não cabe no semestre.** Deixem claro desde o início que é um trabalho
  de disciplina, sem custo e com prazo.
- **Dados reais são dados de pessoas.** Nada de dados pessoais em prints, slides ou no banco
  de desenvolvimento (M09).
- **Se a parceria não der certo** (a organização sumiu, o local não tem internet), a equipe
  continua o projeto normalmente. Registre o que aconteceu: o relato ainda pode valer parte
  do bônus.

## Onde encontrar organizações

| Tipo | Demanda típica |
| --- | --- |
| Associação de moradores | Associados, reserva de espaço, empréstimo de equipamentos |
| Biblioteca comunitária | Acervo, empréstimos |
| Cursinho popular | Matrícula, frequência |
| Horta comunitária | Canteiros, escala de voluntários |
| ONG de assistência | Atendimentos, doações, estoque |
| Cooperativa de reciclagem | Pesagem, repasses |
| Abrigo de animais | Cadastro, adoção, vacinas |
