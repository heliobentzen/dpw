# Checklist de entrega de etapa

Percorra **na véspera**, não na hora. Cada item aqui já derrubou nota de alguma equipe.

## Válido para todas as etapas

- [ ] Todos os itens exigidos na descrição da etapa foram entregues
- [ ] A rubrica correspondente foi lida e usada como guia
- [ ] O PDF abre e está legível (teste em outro computador)
- [ ] Nomes completos e matrículas de todos os integrantes
- [ ] Links funcionam para quem **não** está logado na conta de vocês
- [ ] O docente tem acesso ao repositório
- [ ] Nenhum dado pessoal de terceiros exposto (prints anonimizados)
- [ ] Revisão ortográfica feita por alguém que não escreveu o texto
- [ ] Entregue **antes** do prazo, não no minuto final

---

## Etapa 1 — Definição do tema (semana 8)

- [ ] Matriz de decisão preenchida, com a escolha decorrendo dela
- [ ] Problema formulado como problema, não como solução
- [ ] Organização parceira identificada, com contato real
- [ ] Ata da conversa de diagnóstico, com as 7 perguntas respondidas
- [ ] Personas baseadas em pessoas reais
- [ ] Cenário de uso principal, passo a passo
- [ ] Canvas completo
- [ ] Coluna "não faremos" preenchida e substantiva
- [ ] Critérios de sucesso com metas numéricas e método de medição
- [ ] **Carta de anuência assinada**
- [ ] Máximo 6 páginas

## Etapa 2 — Planejamento (semana 11)

- [ ] Contrato de equipe assinado por todos, com respostas específicas
- [ ] Disponibilidade real declarada por pessoa
- [ ] Backlog com histórias no formato correto
- [ ] Todos os *Must* com critérios de aceite verificáveis
- [ ] MoSCoW aplicado (nem tudo é *Must*)
- [ ] Soma das estimativas dos *Must* cabe na capacidade da equipe
- [ ] Modelo de dados com diagrama e `on_delete` justificado
- [ ] 3+ ADRs com alternativas analisadas
- [ ] Matriz de riscos com mitigação **e** plano B
- [ ] Cronograma semanal até a semana 20
- [ ] Protótipo das telas principais
- [ ] **Evidência de validação do protótipo com a organização**
- [ ] Quadro do projeto (GitHub Projects) populado
- [ ] Repositório com CI configurado e `main` protegida

## Etapa 3 — Desenvolvimento (semana 18)

- [ ] **Sistema no ar, testado hoje** (não "funcionava ontem")
- [ ] HTTPS ativo
- [ ] Login funcionando em produção
- [ ] Uma operação de escrita funcionando em produção
- [ ] CI verde no último commit
- [ ] 20+ testes passando
- [ ] Matriz de acesso testada
- [ ] `check --deploy` sem avisos
- [ ] Nenhum segredo no repositório (verifique também o histórico)
- [ ] README que sobe o projeto em ≤ 5 comandos
- [ ] `docs/deploy.md` reproduzível
- [ ] Plano de teste executado e documentado
- [ ] **Teste com usuário real realizado**, com correções aplicadas
- [ ] Todos os integrantes com commits significativos
- [ ] Quadro do projeto refletindo o estado real

## Etapa 4 — Relatório e encerramento (semana 20)

- [ ] Relatório com todas as 12 seções
- [ ] Resultados confrontados com os critérios da Etapa 1
- [ ] Metas não alcançadas declaradas e analisadas
- [ ] Relato de experiência com cenas concretas e falas literais
- [ ] Bugs conhecidos declarados
- [ ] Uso de ferramentas de IA declarado (Apêndice H)
- [ ] Manual do usuário, escrito para leigos
- [ ] Slides prontos e ensaiados
- [ ] **Vídeo de demonstração gravado** (plano B para falha de rede)
- [ ] Apresentação ensaiada, dentro dos 20 minutos
- [ ] Todos sabem falar sobre partes que não escreveram
- [ ] Termo de transferência assinado
- [ ] Senhas trocadas; contas pessoais removidas dos serviços
- [ ] Duas pessoas da organização com acesso administrativo
- [ ] Ata da devolutiva à organização
- [ ] Avaliação por pares entregue por todos
